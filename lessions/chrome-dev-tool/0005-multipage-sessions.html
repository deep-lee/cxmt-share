Lesson 5: Multi-Page Workflows & Sessions

Orchestrate across tabs and keep your login state.

What You'll Learn

By the end of this lesson, you'll be able to open and switch between multiple browser tabs, preserve login sessions across automation runs, and chain tasks that span different pages.

New Tools

Tool What it does
list_pages List all open tabs/windows with their titles and URLs
select_page Switch the active tab to a specific pageId
new_page Open a new tab (optionally navigated to a URL)
close_page Close a tab by pageId

Knowledge: Tab Management

By default, every tool operates on the currently selected page. To work across tabs:

1. list_pages            → see all tabs: "pageId: 1, 2, 3"
2. select_page (pageId:2)→ switch to tab 2
3. navigate_page / click / fill → act in tab 2
4. select_page (pageId:1)→ switch back to tab 1
Key rule: navigate_page, click, fill, take_snapshot, and take_screenshot all work on the currently selected page. Use select_page to change which page is active.

The new_page tool opens a fresh tab and automatically selects it. close_page closes a tab by ID.

Knowledge: Session Persistence

By default, chrome-devtools-mcp uses a persistent Chrome profile at:

~/.cache/chrome-devtools-mcp/chrome-profile-stable

This means cookies, localStorage, and sessions survive between runs. You can log into a site once, and the session is still there next time you start opencode.

If you used --isolated: The --isolated flag creates a temporary profile that's deleted on close. Remove it from your config if you want persistent sessions.

Custom profile path

You can specify your normal Chrome profile to share cookies between manual browsing and agent automation:

// In opencode.json:
"args": ["-y", "chrome-devtools-mcp@latest",
         "--userDataDir=/Users/you/Library/Application Support/Google/Chrome"]
Caution: Using your real Chrome profile means the agent has access to all your logged-in sessions. Only do this on sites you trust the agent to access.

Knowledge: Chaining Automations

Real workflows often span multiple pages. The pattern is:

1. new_page → "https://site-a.com"
2. authenticate → fill username + password, click sign in
3. new_page → "https://site-b.com" (same auth, cookies shared)
4. extract data from site-b
5. select_page → back to site-a
6. confirm the result

Or for comparison tasks:

1. navigate_page → "https://product-a.com"
2. take_snapshot, extract price
3. new_page → "https://product-b.com"
4. take_snapshot, extract price
5. (agent compares and tells you the result)

Skill: Practice Tasks

Task A: Cross-tab data comparison

Open two tabs: one with https://example.com
and one with https://httpbin.org/anything.
List all pages, switch between them,
and take a screenshot of each.

The agent will use new_page, list_pages, select_page, and take_screenshot.

Task B: Session persistence test

Go to https://httpbin.org/cookies/set?session=test123,
verify the cookie was set, then close opencode.
Restart and ask: check if the session cookie is still there
on https://httpbin.org/cookies

This tests whether your session persists between runs (it should unless you used --isolated).

Task C: Multi-tab scraping

Open the Hacker News front page. For each of the top 3 stories,
open a new tab with that story's URL, take a screenshot,
then close the tab when done.
