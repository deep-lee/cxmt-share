Lesson 2: Navigate, Snapshot, Interact

The core automation cycle: see the page, find elements, act on them.

What You'll Learn

By the end of this lesson, you'll understand the fundamental automation loop — navigate → snapshot → interact → verify — and be able to click links, fill inputs, and wait for page changes.

The Automation Cycle

Every browser automation task follows the same pattern:

1. navigate_page   → go to a URL
2. take_snapshot   → get the page's element tree with [uid] markers
3. click / fill    → act on elements by UID or CSS selector
4. wait_for        → wait for a result to appear
5. take_snapshot   → verify (loop back to step 3 if needed)

The snapshot is the key enabler. It returns an accessibility tree of the page where every interactive element has a unique ID like [17]. You pass that UID to click or fill.

Why snapshots? CSS selectors break when the page changes. UIDs from the accessibility tree are more stable and don't require you to inspect the DOM. The agent handles finding the right UID — you just describe what you want to click.

New Tools for This Lesson

Tool What it does When to use
take_snapshot Get page AX tree with [uid] markers Before every click/fill
click Click element by UID or CSS selector Buttons, links, checkboxes
fill Type text into an input field Single text inputs
fill_form Fill multiple fields at once Forms with 2+ inputs
wait_for Wait for text to appear on page After navigation or clicks
hover Hover over an element Dropdown menus, tooltips
press_key Press a key or combo (e.g., Enter) Keyboard shortcuts, form submission

Knowledge: How Snapshot UIDs Work

When you call take_snapshot, the server returns a text representation of the page's accessibility tree like this:

[1] Heading: "Welcome"
[2] Link: "Get Started"
[3] Text input: "Search..."
[4] Button: "Submit"

The agent (opencode) reads this output and uses the [uid] values (the numbers in brackets) to target click and fill calls. You as the user just describe what you want — the agent handles UID lookup.

Important: The snapshot is stale after any page change. Always call take_snapshot again after navigating, clicking, or submitting a form to get fresh UIDs.

Skill: Your First Automation Task

Here's a concrete task to practice the full cycle. Open opencode and ask your agent to do this:

Go to https://en.wikipedia.org, search for "Browser automation",
click the first result, and take a screenshot

The agent will:

  1. Call navigate_page to go to Wikipedia
  2. Call take_snapshot to find the search input
  3. Call fill to type "Browser automation" into the search box
  4. Call press_key with Enter or click the search button
  5. Call take_snapshot again (fresh UIDs after navigation)
  6. Call click on the first search result
  7. Call take_snapshot to confirm
  8. Call take_screenshot to show you the result

Practice Task

Now try a multi-step automation. Ask your agent to:

  1. Go to google.com
  2. Search for "chrome devtools protocol"
  3. Click the first non-ad result
  4. Take a screenshot

Hint: Google's search box needs a fill followed by press_key with Enter.

Common Patterns

Fill + Enter (search boxes)

fill the search input with "query text"
then press Enter

Fill + Click Submit (forms)

fill the email input with "user@example.com"
fill the password input with "mypassword"
click the "Sign in" button

Wait for content to load

click the "Load more" button
wait for "Results updated" to appear on the page

Multi-field forms

fill_form with:
  name: "Jane Doe"
  email: "jane@example.com"
  message: "Hello, world"
