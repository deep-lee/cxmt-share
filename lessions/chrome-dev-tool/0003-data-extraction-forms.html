Lesson 3: Data Extraction & Form Automation

Pull data out of pages and automate real workflows.

What You'll Learn

By the end of this lesson, you'll be able to extract structured data from any web page, monitor network requests and console output, and automate multi-step form workflows.

New Tools

Tool What it does When to use
evaluate_script Run JavaScript in the page and return the result Extracting data, reading DOM, calling APIs
list_console_messages Get all console.log/warn/error output Debugging SPAs, checking errors
get_console_message Get full details of one console message Inspecting specific log entries
list_network_requests List all network requests since navigation Monitoring API calls, finding XHR/fetch
get_network_request Get full details (headers, body) of one request Inspecting API responses

Knowledge: Three Ways to Extract Data

1. evaluate_script — the Swiss Army knife

evaluate_script runs any JavaScript in the browser page and returns the result as JSON. This is the most flexible extraction tool:

// Extract all links from a page
evaluate_script:
  Array.from(document.querySelectorAll('a')).map(a => ({
    text: a.innerText.trim(),
    href: a.href
  }))
// Extract a table as structured data
evaluate_script:
  Array.from(document.querySelectorAll('tr')).map(row =>
    Array.from(row.querySelectorAll('td')).map(td => td.innerText)
  )
Tip: The JavaScript you pass must be a single expression (not a statement). Use arrow functions with Array.from() for loops. The result is serialized as JSON.

2. Network requests — capture API data

Many modern sites load data via XHR/fetch. You can intercept these responses:

1. navigate_page to the site
2. list_network_requests → find API calls
3. get_network_request with that reqid → read response body
Use case: When a page displays data from an API, get_network_request gives you the raw JSON response — often cleaner than scraping the DOM.

3. Console messages — catch logged data

Single-page apps often log data to the console. You can capture it:

1. Interact with the page (click, fill)
2. list_console_messages → see what was logged
3. get_console_message → expand specific entries

Knowledge: Multi-step Form Automation

Forms with steps or validation require careful sequencing. The pattern is:

1. take_snapshot         → find form fields
2. fill / fill_form      → enter data
3. click "Submit"        → submit the form
4. wait_for "Success"    → wait for validation/redirect
5. take_snapshot         → confirm next page loaded
6. (repeat if multi-step)
Watch for: Inline validation errors. After filling a field, the page might show an error before submission. If automation fails, take a snapshot to check for validation messages.

Skill: Practice Tasks

Task A: Extract headlines from HN

Ask your agent:

Go to https://news.ycombinator.com and extract all story titles and URLs into a structured list

The agent will use navigate_page then evaluate_script to query the DOM and return results.

Task B: Capture API responses

Ask your agent:

Go to https://developer.chrome.com/blog, list the network requests,
find any that look like API calls, and show me their response data

The agent will use list_network_requests to find XHR/fetch calls and get_network_request to read responses.

Task C: Multi-step form

Many sites have a "newsletter signup" or "search" form. Pick any site with a multi-field form and ask:

Go to [site], fill in the search/contact form with test data,
submit it, and check if there's a success message or error

Data Flow: From Browser to File

Once extracted, your agent can save the data to a file:

1. evaluate_script → get JSON data from page
2. (agent writes data to a file in your workspace)
3. You now have a reusable dataset

Just tell the agent: "Save the results to a file called headlines.json".
